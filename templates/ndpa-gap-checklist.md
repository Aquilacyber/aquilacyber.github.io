# NDPA gap checklist

A checklist for seeing where an organisation stands against the Nigeria Data Protection Act 2023 (NDPA) and the Nigeria Data Protection Commission's General Application and Implementation Directive (GAID), which took effect on 19 September 2025.

This is an educational tool for the [GRC track](../tracks/grc.md). It is not legal advice. It was written from the structure of the Act and public summaries of it, checked on 2026-10-03. Before you tell a real organisation it is compliant, read the Act and the directive on [ndpc.gov.ng](https://ndpc.gov.ng/) and take advice from a qualified lawyer or a licensed data protection compliance organisation.

## How to use it

1. Pick the organisation: your own, an invented one, or one that has asked for your help in writing.
2. For each row, mark the status: **Yes**, **Partly** or **No**. Write the evidence you saw, such as a policy name, a screenshot or a log, or write "none".
3. For every Partly or No, write an action, an owner and a date.
4. Fill in the summary at the end.

Never keep real customer data in this document. Describe it by type.

## 2. Registration and governance

| Check | Status | Evidence or note |
|---|---|---|
| If we are of major importance, we are registered with the NDPC | | |
| If we are of major importance, a Data Protection Officer with suitable knowledge is appointed (section 32) | | |
| A written data protection policy exists and senior management has approved it | | |
| Staff who handle personal data have been trained, and we keep a record | | |
| We know whether we must file a compliance audit return with the NDPC, and when. Check the current deadline on the NDPC site, because it has changed before | | |

## 3. Records and lawful basis

| Check | Status | Evidence or note |
|---|---|---|
| We keep a data inventory: what personal data we hold, where, why and who sees it | | |
| Every processing activity has a stated purpose | | |
| Every processing activity has a lawful basis: consent, contract, legal obligation, vital interests, public interest or legitimate interests | | |
| We collect only the data we need for each purpose | | |
| We have a retention schedule and delete or anonymise data when the period ends | | |
| We have a way to correct inaccurate data | | |

## 4. Transparency and consent

| Check | Status | Evidence or note |
|---|---|---|
| A privacy notice says who we are, what we collect, why, the lawful basis, who we share it with, where we send it, how long we keep it, what rights people have and how to reach us | | |
| The notice tells people they can complain to the NDPC | | |
| Where we rely on consent, it is freely given, specific, informed and clear. Silence and pre-ticked boxes are not used | | |
| People can withdraw consent as easily as they gave it | | |
| We record when and how each person consented | | |

## 5. Data subject rights

| Check | Status | Evidence or note |
|---|---|---|
| We have a documented process for requests to access, correct, delete, restrict, port or object | | |
| We verify the identity of the person asking before we release anything | | |
| We know the deadline for responding. Check the Act and the directive | | |
| We keep a log of requests and outcomes | | |
| People can object to marketing and to decisions made only by automated means | | |

## 6. Security

| Check | Status | Evidence or note |
|---|---|---|
| Access to personal data is limited to people who need it | | |
| Multi-factor authentication protects accounts that reach personal data | | |
| Personal data is encrypted in transit, and at rest where the risk calls for it | | |
| Systems are patched and scanned for vulnerabilities on a schedule | | |
| Logs record who accessed personal data, and someone reviews them | | |
| Backups exist and restores have been tested | | |
| Security controls have been tested by an internal check or an independent test | | |

## 7. Breach management

| Check | Status | Evidence or note |
|---|---|---|
| Our incident response plan covers personal data breaches | | |
| We keep a register of every breach, including those we did not report | | |
| We can notify the NDPC within 72 hours of becoming aware of a breach that is likely to put people's rights at risk | | |
| We can tell affected people without delay when the risk to them is high | | |
| The plan names who decides, who writes the notice and who speaks to the regulator | | |
| We have tested the process in a drill in the last year | | |

## 8. Processors and third parties

| Check | Status | Evidence or note |
|---|---|---|
| We have a list of everyone who handles personal data for us | | |
| Each has a written contract that covers security, confidentiality, sub-processors and what happens at the end | | |
| We checked each one's security before we signed | | |
| We review them regularly and know how to end the relationship and recover our data | | |

## 9. Transfers outside Nigeria

| Check | Status | Evidence or note |
|---|---|---|
| We know every place where personal data leaves Nigeria, including cloud services and support staff abroad | | |
| Each transfer has a valid basis, such as an adequacy decision, binding corporate rules, contract clauses, an approved code or a certification | | |
| We have recorded the basis and checked whether the directive requires us to file anything with the NDPC | | |

## 10. Impact assessments

| Check | Status | Evidence or note |
|---|---|---|
| We have a way to spot processing that is likely to cause high risk to people | | |
| We carry out a data protection impact assessment where required (section 28) | | |
| We consult the NDPC where an assessment shows a high risk we cannot reduce | | |
| We have checked whether the directive requires us to file the assessment | | |

## 11. Children and sensitive data

| Check | Status | Evidence or note |
|---|---|---|
| We know whether we collect data from children and how we confirm age | | |
| We obtain the consent of a parent or guardian where the law requires it | | |
| Sensitive data has stricter controls than ordinary data | | |
